# سياسة الإصدارات (RELEASE_POLICY.md) — الدليل التشغيلي

> القرار البنيوي في [ADR 0003](adr/0003-release-versioning-policy.md). هذه
> الصفحة هي دليل التنفيذ اليومي للفريق — تُحدَّث مع كل تغيير في الآلية.

## 1. قواعد سريعة (مرجع الجيب)

| الوضع | ماذا تفعل |
|---|---|
| إصلاح عطل/ثغرة | `PATCH+1` (2.0.0 → 2.0.1) |
| ميزة/لغة/محرك جديد | `MINOR+1` وإعادة العدّاد (2.0.0 → 2.1.0) |
| كسر توافق (تخزين/صيغة حزم/SDK) | `MAJOR+1` |
| بيتا على مسار نشط | `-betaN+1` + `versionCode+1` (آلي — weekly-beta) |
| ترقية بيتا → رسمي | أزل اللاحقة، `versionCode+1`، استيفاء §4 من ADR 0003 |

- الوسم: `v<versionName>` حرفيًا. أي اختلاف = فشل CI (بوابة release.yml).
- `versionCode` رتيب صاعد لا يُعاد استخدامه مطلقًا (يبدأ 1 في v1.0.0).

## 2. كيف يُقطع إصدار رسمي (runbook)

1. استوفِ شروط ADR 0003 §4 (CI أخضر، اختبارات ناجحة، صفر أعطال حرجة، مدة بيتا).
2. حدّث `gradle.properties` (versionName بدون لاحقة + versionCode جديد) وCHANGELOG.
3. افتح PR → مراجعة → دمج في main.
4. وسِّم الالتزام النهائي: `git tag v1.0.1 && git push origin v1.0.1`.
5. CI (release.yml) يبني ويوقّع وينشر تلقائيًا: APK + AAB + 8 حزم flex + SHA256SUMS.
6. راجع الـRelease المنشور (الوصف من `.github/RELEASE_BODY.md`، علامة latest).

## 3. البيتا الأسبوعية (آلية بالكامل)

- `weekly-beta.yml` يعمل كل أحد 03:00 UTC:
  - يتحرك فقط على مسار ما قبل نهائي نشط (`-betaN/-rcN`) — على إصدار مستقر يتوقف.
  - يتوقف إن لم توجد التزامات منذ آخر وسم بيتا (بلا دوران فراغ).
  - يرفع `-betaN→-betaN+1` و`versionCode+1`، يلتزم ويوسم، ثم يستدعي
    `release.yml` كسير قابل لإعادة الاستخدام (يتجاوز قاعدة عدم تكرار
    GITHUB_TOKEN).
- كل بيتا تُنشر `prerelease` تلقائيًا (كشف النمط `-beta|-rc|-alpha`) ولا تُعلن
  `latest` — حماية المستخدمين المستقرين من التحديث التلقائي نحو بيتا.
- بيان البيتا من `.github/RELEASE_BODY_BETA.md`.

## 4. قناة البيتا على Google Play (عند التوزيع)

| المسار | الجمهور | المصدر |
|---|---|---|
| Internal testing | الفريق | كل بيتا أسبوعية (APK/AAB من CI) |
| Closed testing | مختبرو 1000 (المرحلة 4) | بيتا مستقرة بعد أسبوع بلا أعطال حرجة |
| Production | الجمهور | الإصدارات الرسمية بعد استيفاء §4 |

قاعدة الإغلاق: أي ثغرة أمنية حرجة تُجمّد القنوات كلها حتى إصدار PATCH.

## 5. التوثيق المطلوب مع كل إصدار (checklist)

- [ ] مدخل CHANGELOG بالعربية (ماذا ولماذا، بصيغة المستودع القائمة).
- [ ] بيان Release + SHA-256 (يولّدها CI حرفيًا).
- [ ] تحديث `docs/COVERAGE.md` إن تغيرت قاعدة التغطية.
- [ ] تحديث `docs/adr/` إن اتُّخذ قرار بنيوي جديد خلال الدورة.
