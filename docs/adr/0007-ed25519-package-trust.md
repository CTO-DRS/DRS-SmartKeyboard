# ADR 0007 — سلسلة توريد الحزم: توقيع ed25519 مثبّت المفتاح قبل أي فك ضغط

- **الحالة:** مقبول
- **التاريخ:** 2026-10
- **القرّاء:** الفريق الهندسي، مدققو الأمن، مشرفو إصدارات الحزم
- **النطاق:** مبادرة M0.3 من المرحلة 0 لخريطة 2026–2028 (أمن سلسلة توريد الحزم):
  توقيع حزم flex الثماني الرسمية، بوابة الكتالوج الموقّع، والتحقق قبل فك الضغط

## السياق

مركز الحزم (DRS Package Center) ينزّل حزم `.flex` من الكتالوج الرسمي
(`packages/manifest.json`) ويثبّتها عبر نظام الامتدادات الأصلي. كانت
التحصينات القائمة (HTTPS فقط، SHA-256، بوابات id/version/type) تحمي من
التلف والتلاعب العابر، لكنها لم تكن تثبت **المنشأ**: أي من يستطيع نشر
إصدار GitHub مستقبلاً — أو اختراق حساب النشر — يستطيع نشر كتالوج سليم
البنية بمحتوى عدواني. الـSHA-256 يثبت «الملف هو ما قاله الكتالوج»،
لا «الكتالوج هو ما قاله المشروع».

## القرار

### 1) المفتاح مثبّت في الكود، لا مكتشف من الشبكة

`DrsPackageTrust` يثبّت المفتاح العام للمفتاح `cto-drs-release-1`
(32 بايت، hex) داخل الكود. لا اكتشاف مفاتيح عن بعد، لا TOFU، لا تجاوز:
تدوير المفتاح يأتي كمعرّف مثبّت جديد في إصدار تطبيق جديد. البذرة
الخاصة (32 بايت خام) تعيش في `.local-secrets/` خارج git عمدًا، ولا
يحملها إلا `tools/drs_package_sign.py`.

### 2) أداة التوقيع تُثبت نفسها قبل كل توقيع

`tools/drs_package_sign.py` (ed25519 نقي على RFC 8032) يشغّل اختبار
الذات على متجهات §7.1 الرسمية (TEST 1–3: توقيع + تحقق + رفض العبث)
قبل كل عملية توقيع — أداة لا تثبت صحتها لا تلمس بذرة النشر. المتجه
الذهبي العابر للتنفيذين (وقّعته الأداة، تحققه شجرة Kotlin في
`DrsM03Ed25519VectorsTest`) يثبت أن التنفيذين المستقلين يتفقان بايت-بايت.

### 3) تنفيذ Kotlin مستقل ومُدقَّق على المتجهات الرسمية

`DrsEd25519` ينفّذ RFC 8032 §5.1 على BigInteger بلا اعتماديات طرف
ثالث. التحقق يتبع نص §5.1.7 حرفيًا: رفض S >= L (بوابة القابلية
للتمديد)، رفض y >= p عند فك النقاط، والمعادلة **المنسوجة بالكامل**
[8][S]B == [8]R + [8][k]A — المتشارك 8 في الطرفين، كما يقول النص.
(الدرس الموثق: نسخة أولى نقصها ضرب الطرف الأيمن بالمتشارك 8 كشفها
المتجه الرسمي فورًا — لذلك المتجهات الرسمية إلزامية، لا «الثقة».)

### 4) الكتالوج بلا توقيع = كتالوج غير موثوق (fail-closed)

`parseManifest` يفرض زوج `signature`/`pubkey_id` إلزاميًا: أي مدخل
ناقص الزوج أو يسمّي مفتاحًا مجهولًا يُسقَط تمامًا كمدخل بمعرّف غير
صالح. الحزم الثماني الرسمية موقّعة في الكتالوج نفسه، والتحقق 8/8
VALID مقابل المفتاح المثبّت شرط قبل الدمج.

### 5) التحقق قبل فك الضغط

`verifyFile` يفحص (الحجم → SHA-256 → توقيع ed25519 فوق بايتات الملف
الخام) قبل أن يلمس مُفك الضغط الملف إطلاقًا؛ `importVerifiedPackage`
لا يفتح الأرشيف إلا بعد نجاح كل البوابات. الحقن الاختباري
(`signatureVerifier`) يثبت الترتيب في `DrsP8UpdateSurfaceTests`.

## النتائج

- سلسلة توريد الحزم تثبت المنشأ تشفيريًا، لا بالعادات الإدارية.
- كل بوابة قابلة للاختبار بمعزل عن الشبكة، ومثبتة في الاختبارات.
- كلفة التشغيل: تحقق ed25519 واحد لكل تنزيل (أقل من مللي ثوانٍ على
  أي جهاز حديث) — لا تأثير محسوس على التثبيت.
- القرار المفتوح القادم: نشر بذرة النشر في تخزين بارد خارج بيئة
  التطوير (قرار مالك المشروع) قبل أول إصدار رسمي مُدار بهذه السلسلة.
