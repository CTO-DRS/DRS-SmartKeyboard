# التحديثات الأمنية — سياسة ربع سنوية معلنة (المرحلة 3، المهمة 7)

> يربط إيقاف الأمان بإيقاف الإصدارات المعمول به في RELEASE_POLICY.md
> وADR 0003، ويحدد ماذا يعلن ومتى وأين.

## الإيقاع

| الحدث | الدورية | القناة |
|---|---|---|
| نافذة تحديث أمني عادية | **ربع سنوية** — مع أول إصدار مستقر لكل ربع | Releases + CHANGELOG + إعلان في قنوات الدعم |
| رقعة أمنية خارج النافذة (حرجة فقط) | فورية عند جاهزية الإصلاح | Releases مع وسم patch (2.2.1 مثلاً) |
| تمرين canary وCodeQL وgitleaks | كل دفعة + أسبوعيًا مجدولة | security.yml |
| إعادة فحص خارجية (عند تمويلها) | ربع سنوية حسب PENTEST_PROGRAM.md | تقرير ملخص علني بعد الإصلاحات |
| تقرير الشفافية | نصف سنوي | docs/TRANSPARENCY_REPORT.md |

## نافذة الإصدار الأمني الربع سنوية — المحتوى الثابت

1. تحديث تبعيات الإنتاج ذات التخوم الأمنية (Gradle/JDK target/runtime
   libs) إلى آخر patch — بناءً على تنبيهات Dependabot المولدة من
   security.yml.
2. نتائج gitleaks/CodeQL منذ النافذة السابقة: كل تنبيه مقفل بحالة
   (إصلاح/مغلق بمبرر) — لا تنبيه مفتوح يعبر نافذتين.
3. تشغيل privacy canary على آخر شجرة مستقرة + نشر بصمة الشهادة
   الحالية والتحقق من ثباتها (e7235043… منذ v1.27.0).
4. سجل أي إعلان ثغرة واصلنا عبر SECURITY.md — مع الإقرار بالزمن
   الفعلي مقابل SLA.

## نافذة الدعم

| القناة | النطاق |
|---|---|
| آخر إصدار مستقر (latest) | كل الأنواع: حرجة/عالية/متوسطة/منخفضة |
| الإصدار المستقر السابق | الحرجة والعالية فقط |
| إصدارات ما قبل النهائي (alpha/beta/rc) | إصلاحات تصل عبر الإصدار التالي فقط — لا نوافذ رجعية |

## معالجة CVE والإفصاح

- كل ثغرة مؤكدة تحصل على معرف داخلي (DRS-SEC-YYYY-NN) وسجل في
  GitHub Security Advisories عند الطلب المشترك مع الباحث.
- الإعلان العام يأتي مع الرقعة (لا إعلان بلا إصلاح)، ويذكر: الخطورة،
  المسار، الإصدارات المصابة، الإصدار المصلح، وشكر الباحث إن رغب.
- التزامنا بالمواعيد موثق في SECURITY.md (72 ساعة إقرار، 7 أيام
  تقييم، 30 يوم إصلاح للحرجة/العالية).

## ماذا لو كسرت canary نفسها؟

لو أثبتت ثغرة أن أحد ادعاءات PRIVACY_POLICY.md غير صحيح (مثلاً مسار
شبكي غير معلن)، هذا تلقائيًا High+ في SECURITY.md، ويترتب عليه: رقعة
خارج النافذة العادية + إشعار في أول فقرة من بيان الإصدار + تحديث
سياسة الخصوصية قبل رقعة المستخدم التالية.
