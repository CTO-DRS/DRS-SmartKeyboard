# بنية DRS Smart Keyboard (ARCHITECTURE.md)

- **النطاق:** يوثّق هذا المستند البنية الفعلية للكود كما هي على `main` من الإطلاق الأول v1.0.0 وما بعده — لا نوايا مستقبلية.
- **التحديث:** يُحدَّث مع كل تغيير بنيوي جوهري (إضافة/إزالة وحدة، تغيير مسار بيانات أساسي).
- **التاريخ:** 2026-10 (خريطة الطريق الكبرى — المرحلة 1، المهمة 2).

## 1. نظرة عالية المستوى

تطبيق أندرويد من نوع **Input Method Editor (IME)** بلوحة مفاتيح ذكية، مكتوب بـ Kotlin
وعمليات Compose، مبني على توزيع متعدد الوحدات Gradle:

```
DRS-Smart-Keyboard/
├── app/          ← التطبيق: الخدمات، محرك الكتابة، طبقة DRS، الواجهات
├── lib/          ← 8 وحدات مكتبية قابلة للاختبار المعزول
│   ├── android/            ← غلافات أدوات أندرويد العامة
│   ├── color/              ← أنظمة الألوان والتحويلات
│   ├── compose/            ← عناصر ومساعدات Compose المشتركة
│   ├── jetpref/datastore-model            ← نموذج التفضيلات (كائنات مُعلنة)
│   ├── jetpref/datastore-model-processor  ← معالج KSP لتوليد كود التفضيلات
│   ├── jetpref/datastore-ui               ← واجهات ربط التفضيلات
│   ├── jetpref/material-ui                ← مكوّنات إعدادات بنمط Material
│   ├── kotlin/             ← أدوات Kotlin العامة (collections، coroutines…)
│   └── snygg/              ← محرك السِمات التعريفي (قواعد نمطية للسِمات)
├── packages/     ← 8 حزم رسمية بصيغة .flex (سِمات وإضافات) موقعة SHA-256
├── utils/        ← أدوات بناء غير Gradle (تحويل قواميس fcitx5، توليد spellcheck…)
└── docs/         ← التوثيق (هذا المجلد) + إقرارات البنية ADR
```

**القاعدة البنيوية الجوهرية:** اتجاه الاعتماديات يسير في اتجاه واحد فقط —
`app → lib/*` ولا شيء عائدًا. وحدات `lib` لا تعرف بعضها إلا عبر العقد المُعلنة،
وهذا ما يسمح باختبار 862 وحدة على JVM بلا جهاز أندرويد.

## 2. الوحدتان الخدميتان (نقاط الدخول النظامية)

| الخدمة | الملف | الدور |
|---|---|---|
| `DrsImeService` | `app/.../DrsImeService.kt` | خدمة IME الرئيسية: استقبال أحداث المفاتيح، إدارة نافذة الإدخال، دورة الحياة |
| `DrsSpellCheckerService` | `app/.../DrsSpellCheckerService.kt` | مزوّد التدقيق الإملائي النظامي ( SpellCheckerService ) |
| `DrsApplication` | `app/.../DrsApplication.kt` | تهيئة العملية: تثبيت DrsCrashHandler، إقلاع أنظمة DRS |

على `DrsImeService` تُركَّب «دروع» دفاعية موثقة في سجل التغييرات (استدعاءات IMS
الست، درع تسابق المحرر، بوابة `imeWindowShown`) — هذه طبقة استقرار تُحاكى في
اختبارات JVM عبر عقود المحرك.

## 3. حزم `ime/` — محرك لوحة المفاتيح

كل حزمة تحت كود إنتاج فعلي ضمن `app/src/main/kotlin/com/drs/smartkeyboard/ime/`:

| الحزمة | المسؤولية |
|---|---|
| `core` | `SubtypeManager` وإدارة اللغات/التنويعات الفرعية |
| `input` | خط أنابيب إدخال الأحداث (لمس/فيزيائي) نحو المحرر |
| `text/key`, `text/composing`, `text/keyboard` | حالة المفاتيح، التركيب (composing)، تخطيطات لوحات النص |
| `editor` | محرر الإدخال: الالتزامات المجمعة، undo/redo، إدارة الحقل المستهدف |
| `nlp` | مدير NLP: `NlpManager`، مزودو `latin` و`han`، `AutocorrectDecider`، قواعد الترقيم، مرشحو الاقتراح |
| `dictionary` | طبقة القواميس (تحميل/استعلام) المبنية فوق حزم flex |
| `clipboard` + `clipboard/provider` | الحافظة الداخلية ومزوّد الوسائط (نسخ/لصق ملفات ببوابات أمنية) |
| `media/emoji`, `media/emoticon` | لوحات الإيموجي والإيموتيكون |
| `voice` | الإدخال الصوتي مع احترام وضع التعرف (on-device) وبوابة حقول كلمة السر |
| `theme` | ربط محرك snygg بواجهة الكيبورد |
| `smartbar`, `popup`, `sheet` | الشريط الذكي، المنبثقات، الأدراج السفلية |
| `landscapeinput` | وضع الإدخال الأفقي (`ExtractedInputRootView`) |
| `window` | إدارة نافذة IME والارتفاعات ووضوح الحواف |
| `lifecycle` | ربط دورة حياة الخدمة بأنظمة DRS |

## 4. حزمة `drs/` — طبقة التخصيص والذكاء (37 ملفًا)

الطبقة المضافة فوق محرك الكتابة، وكلها تعمل **محليًا بلا شبكة**:

| النظام | الملفات | الدور |
|---|---|---|
| الحالة المركزية | `DrsStore`, `DrsRuntimeState`, `DrsModels` | مخزن الحالة الوحيد (دفعة كل 15 ثانية)، حالة التشغيل الحية |
| التكامل | `DrsIntegration`, `DrsSystems`, `DrsUnified` | نقطة الربط بين الخدمة وأنظمة DRS، تجميع الأنظمة الموحد |
| التعلم التكيفي | `DrsAdaptationEngine` | تعلم أسلوب الكتابة الشخصي (قاموس تكيفي) |
| الاقتصاد | `DrsEconomy` | نظام نقاط/مكافآت يومية (كل شيء محلي) |
| الاختصارات | `DrsShortcuts`, `DrsTextTools`, `DrsTechToolbarKeys` | اختصارات ذكية، أدوات نصية، شريط تقني |
| الإحصاءات | `DrsDailyStats`, `DrsEventLog`, `DrsPerformance` | إحصاءات يومية، سجل أحداث محدود/مطهّر (حلقة 200)، قياس زمن المفتاح (ميكروثانية) والذاكرة |
| التشخيص | `DrsCrashHandler`, `DrsCrashReports` | سجل أعطال محلي مطهّر + سجل أعطال بنيوي JSON محدود (بلا أي محتوى مستخدم) |
| الملفات الشخصية | `DrsProfileManager` | ملفات كتابة متعددة |
| النسخ الاحتياطي | `DrsBackup` | تصدير/استيراد أرشيف محدود القراءة (64KiB بوابة) |
| الألواح الذكية | `DrsPanelSmart`, `DrsSmartPanels`, `ui/*` | 19 شاشة/لوح Compose: مركز التحكم، التشخيصات، الأداء، الملفات، الاختصارات، اللوحات الموحدة |

**قسّم `ui/`**: شاشات Compose كاملة (الموحد الأساسي/الكتابة/الأنظمة/الأدوات/الإحصاءات،
مركز التحكم، التقنيات، الإيماءات، الترحيب) — كلها تقرأ من `DrsStore` عبر State.

## 5. نظام الحزم `.flex`

- الصيغة: أرشيف مضغوط يعلن `manifest.json` بـ `package_id` + الإصدار + hash.
- كتالوج التحميل يفرض: نمط إصدار سليم، معرّف صالح، hash سداسي، HTTPS حصرًا — قبل أي مسار ملف.
- الاستيراد يُطهّر أسماء الأصول (قطاع واحد + احتواء كانوني) ويدقق التوقيع.
- حزم `packages/pkg-*.flex` الثماني الرسمية متطابقة عبر الخطّين التاريخيين (نفس SHA-256)
  وتُنشر مع كل Release تلقائيًا من CI.

## 6. مسار البيانات (من اللمسة إلى الحرف)

```
حدث لمس/مفتاح
  → DrsImeService (دروع الحماية)
  → input pipeline (تصنيف/تحويل)
  → editor (composing + التزامات آمنة استثنائيًا)
  → nlp (اقتراح/تصحيح عبر مزود اللغة) ← DrsAdaptationEngine (تخصيص محلي)
  → commit إلى الحقل المستهدف
  → DrsPerformance.recordKeyLatency + DrsDailyStats + DrsEventLog (قياس، بلا محتوى)
```

**عقد الخصوصية البنيوي:** لا شيء في هذا المسار يلمس الشبكة. سجل الأحداث والأعطال
والأداء كلها حلقات محدودة في RAM/قرار داخلي، ولا تحتوي نصًا مستخدمًا مطلقًا —
وتفاصيل القيود موثقة في `docs/adr/0004-crash-reporting-privacy.md`.

## 7. مصادر البناء (source sets)

| المصدر | الغرض |
|---|---|
| `main` | الكود المشترك |
| `beta` | تخصيصات بناء بيتا (applicationIdSuffix `.beta`) |
| `test` | 62 ملف اختبار JVM (Kotest FunSpec + kotest-property) — 862 اختبارًا |
| `androidTest` | اختبارات قياس الأداء المرجعي (buildType `benchmark` مُهيأ) |

**أنواع البناء:** `debug`، `beta` (R8 + تقليص موارد + بوابات تحقق dex)،
`release` (نفس بوابات beta + توقيع)، `benchmark` (مشتق من release للتقييس).
التغطية عبر Kover 0.9.8 (`useJacoco()`) — docs/COVERAGE.md.

## 8. CI/CD

| السير | المُحفِّز | الوظيفة |
|---|---|---|
| `android.yml` | push على `main`/`unify/**`/`roadmap/**` + PR | بناء debug + 862 اختبارًا + lint (غير حاجز بسبب خلل AGP K2 المعلوم) + تحقق بنية APK + رفع تقرير التغطية |
| `release.yml` | دفع وسم `v*` + يدوي | اختبارات كبوابة → فك keystore من الأسرار → بناء APK/AAB موقّع → SHA256SUMS → نشر Release (بيتا = prerelease تلقائيًا) |
| `weekly-beta.yml` | cron أسبوعي (أحد 03:00 UTC) + يدوي | يرفع رقم بيتا تلقائيًا (versionName+versionCode) ويوسم — ويستسلم إن لم توجد التزامات جديدة منذ آخر بيتا |

التوقيع موحّد حصريًا داخل CI (أسرار `DRS_KEYSTORE_*`) — لا توقيع محلي في مسار الإصدار.

## 9. استراتيجية الاختبار

1. **عقود المحرك على JVM:** كل دروع IME لها اختبارات عقود (862 اختبار Kotest، منها
   اختبارات خصائص kotest-property بميزانيات استبعاد مضبوطة للاختبارات المتقلبة).
2. **اختبارات انحدار أمنية:** كل إصلاح أمني (11 إصلاح المرحلة 8) مقترن باختباره
   (32 اختبار ZipUtils/parseManifest/assetName مثالًا).
3. **اختبارات أداء بنيوية:** نافذة قياس زمن المفتاح (حلقة 256) تُختبر تحت إجهاد
   عشرات الآلاف من التسجيلات (دقة النافذة، ترتيب النسبئية، ثبات السعة، صفر تخصيص).
4. **تغطية Kover:** مفعّلة في CI على debug — القاعدة والهدف (≥85%) موثقة في `docs/COVERAGE.md`.

## 10. قرارات البنية المعمول بها

- **ADR 0001** — استراتيجية توحيد الخطّين (قاعدة drs-smart + نقل الإصلاحات بشجرة).
- **ADR 0002** — خريطة الإصلاحات الأمنية الـ11 المنقولة.
- **ADR 0003** — سياسة الإصدارات والترقيم (Semver + versionCode رتيب + قنوات).
- **ADR 0004** — تشخيص الأعطال بلا مخلّخصوصية (رفض Crashlytics الافتراضي، سجل محلي مطهّر).
